# Задачи команды по среде обучения поисковых агентов

Распределение, согласованное Сергеем 2026-10-30. Вова — бенчмарки, задачи и джаджи; Коля — инфраструктура снятия бенчмарков поверх харнесса и поиска; Сергей — агент, харнесс и модели; Дима — база данных и поисковые ручки. Даты и объём первых задач пока не определены.

## Папки и первые задачи

План от 2026-10-31. Реализованы `contracts/`, `agent/`, моковый пример и автономные тесты; остальные пути пока целевые. Полный план — в [STRUCTURE.md](STRUCTURE.md). Правила веток и ревью — в [CONTRIBUTING.md](../CONTRIBUTING.md).

| Исполнитель | Участок | Первый проверяемый результат |
|---|---|---|
| Сергей | `src/search_rl_env/agent/`, затем `training/` | Один эпизод: наблюдение → действие модели → поисковая ручка → результат в историю → завершение и сохранённая траектория |
| Дима | `src/search_rl_env/search/` | Загруженный корпус и вызовы поиска и чтения по постоянным id на ручном примере |
| Коля | `src/search_rl_env/evaluation/` | Сохранённый результат плюс эталон → запуск оценщика Вовы → таблица метрик по вопросам и набору |
| Вова | `src/search_rl_env/benchmarks/`, пример в `examples/fixtures/` | Небольшой синтетический набор, эталоны и ожидаемые оценки нескольких правильных и ошибочных результатов |

Общие форматы в `contracts/` согласуют владельцы соединяемых компонентов по [CONTRACTS.md](CONTRACTS.md). При добавлении кода каждый исполнитель добавляет проверки своего участка; вычисление метрики принадлежит Вове, массовое выполнение этой метрики — Коле.

Первый интерфейс харнесса: `await run_episode(task, model, search, config) -> EpisodeResult`. Для Димы зафиксирован `SearchBackend.search(query, *, corpus_id, corpus_revision, limit) -> list[SearchHit]`; для Коли — задача без эталонов, результат с историей, usage, причиной остановки и `save_episode`. Модель сама определяет число поисков; отдельный лимит поисков по умолчанию выключен. Проверяемый пример: `python examples/run_episode.py --output runs/demo/episode.json` после установки по README. Реальный поиск, runner, оценщики и MLflow остаются отдельными интеграциями; общего одобрения контракта Димой и Колей этот PR не заменяет.

## Сергей

AI engineer middle в Яндексе. Ведёт харнесс: код, который управляет взаимодействием модели с инструментами среды.

Первый участок разработки:

- вместе с Димой определить формат наблюдения, действия и результата инструмента;
- реализовать цикл модели: история → вызов Qwen через OpenRouter → поисковое действие → результат в историю → следующий вызов;
- задать промпт, формат вызовов инструментов, управление контекстом и завершение эпизода;
- реализовать состояние и ограничения эпизода, финализацию и передачу результата оценщику;
- связать харнесс с запуском оценки Коли, затем подключить сбор роллаутов и RL-обучение;
- вести постановку эксперимента и статью.

Первый результат: агент проходит задачу в нашей среде, а его действия и доступный контекст видны в сохранённой траектории. Вызов модели через API входит в эту задачу харнесса.

## Дима

Backend middle в Яндексе. Ведёт базу данных, хранение корпуса и поисковые ручки, которыми пользуется агент.

Первый участок разработки:

- организовать загрузку и хранение корпуса, постоянные id документов и чанков, версии данных;
- построить поисковый индекс и реализовать ручку поиска с ранжированными результатами и сниппетами;
- реализовать получение текста документа или чанка по id;
- вместе с Сергеем согласовать запросы, ответы, ошибки и ограничения поисковых ручек;
- обеспечить работу параллельных запросов, обработку ошибок и телеметрию поиска.

Первый результат: корпус загружен, по запросу находятся документы с постоянными id, а текст можно получить через согласованные ручки без участия модели.

## Коля

Backend-стажёр в Т-Банке. Ведёт инфраструктуру снятия бенчмарков поверх харнесса Сергея и поискового бэкенда Димы. Вова задаёт задачи, метрики и джаджей; Коля обеспечивает их воспроизводимый запуск и сбор результатов. Контракт и ревью — у Сергея и Димы.

Вход: набор вопросов с эталонными документами, конфигурация модели и готовый харнесс Сергея. Выход: результаты по каждому вопросу, общие метрики, затраты и сравнение двух прогонов.

Задачи по очереди:

1. Подключение оценщиков Вовы к сохранённым результатам: загрузить ответы, вызвать нужную метрику или джаджа, собрать оценки по вопросам и по набору. Для первого бесплатного примера достаточно небольшой ручной разметки и детерминированной метрики.
2. Команда запуска оценки: передать вопросы готовому харнессу, сохранить эпизоды, продолжить прерванный пакет по id задач. Корпус, лимиты и конфигурацию модели сохранить вместе с результатом.
3. Сравнение двух прогонов: исходная и обученная модель на одних вопросах, изменения метрики и затрат, список улучшившихся и ухудшившихся задач. Сохранить таблицы и артефакты в MLflow.

Первый результат: команда получает сохранённые ответы агента и эталон Вовы и выдаёт корректную метрику с разбивкой по вопросам. Следующий результат — исходная и обученная модели оцениваются одинаковой командой, а их результаты автоматически сводятся в таблицу. Инфраструктурные сбои и отсутствующие ответы показываются явно.

## Вова

Развивает AI B2B SaaS. Ведёт бенчмарки: содержание задач, эталонную разметку, метрики и джаджей.

Первый участок:

- вместе с Сергеем выбрать открытый корпус и один понятный сценарий поиска;
- подготовить небольшой ручной пример документов и вопросов для разработки, затем пилот на 50–100 вопросов;
- для каждого вопроса указать релевантные документы, объяснить связь и проверить, хватает ли корпуса для решения;
- добавить похожие, но неподходящие документы; проверить неоднозначные формулировки;
- определить правила разметки, метрики и разбиение train/dev/test, согласовав с Сергеем награду для обучения;
- подготовить оценщики: проверки по эталону, а для задач со смысловой оценкой ответа — промпты и конфиги джаджей;
- проверить оценки джаджей на ручной выборке и зафиксировать их версии и параметры;
- вести список ошибок и ручную проверку выборки результатов агента.

Первый результат: пакет вопросов с эталонами и понятными правилами оценки, а также пример работы оценщика на нескольких правильных и ошибочных результатах. Коля подключает эти оценщики к массовому прогону. Для роста обучающего набора конвейер генерации можно распределить отдельно после проверки пилота.

## Первый общий запуск

Сначала Сергей и Дима фиксируют контракт поисковых ручек на одном примере Вовы. Сергей и Коля согласуют вызов харнесса и формат результатов; Вова и Коля — интерфейс оценщиков. Затем работа идёт параллельно.

Первый общий результат: инфраструктура Коли запускает вопросы Вовы → агент в харнессе Сергея обращается к поисковым ручкам Димы → оценщики Вовы дают оценки → инфраструктура Коли сохраняет метрики, затраты и отчёт. После измерения исходной метрики подключаем обучение.

Начальный доступ к модели Сергей планирует через OpenRouter. Точный model id и бюджет выбираются перед платным прогоном; создание аккаунта не считается разрешением на расходование средств.
