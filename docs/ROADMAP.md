# Этапы разработки

Этап M0 подробно описан в [плане перехода на OpenAI Agents SDK](OPENAI_AGENTS_MIGRATION.md).

Первый результат команды — рабочий статический харнесс и воспроизводимые исходные замеры. Затем сравниваем static, Hermes-like memory-only и prompt-evolution на одном потоке. Качество определяет независимая оценка первой попытки на следующих запросах.

## Ближайший замер

Статический runtime на OpenAI Agents SDK, многораундовый поиск и закрытый Recall@10 работают. На 100 вопросах BrowseComp-Plus EN зафиксированы прямой Lucene/BM25, прямой Qwen3-Embedding-8B с FAISS и агентный `bounded`. Последующие проверки измерили настройку reasoning, размер сниппета и лимит ходов. Ближайшая поисковая абляция проверяет, какие свидетельства теряются при отборе в итоговый топ‑10. Для M1 нужна отдельная проверка ответов на связанных SQL + RAG-задачах с публичной и собственной панелями. [Результаты](EXPERIMENTS.md#измерения-от-18-ноября-2026) · [Порядок прогонов и критерии](EXPERIMENTS.md#план-замеров-на-публичных-наборах).

| Этап | Условие готовности |
|---|---|
| M0 | Агент самостоятельно отвечает через SQL/search в окружении без Verifiers, ответ проверяет независимый оценщик |
| M1 | Принята воспроизводимая таблица статического агента на открытых и собственных задачах |
| M2 | В пилоте выполнены discovery → изменение промпта → replay → решение критика → публикация для нового запроса. Работают static и memory-only |
| M3 | Парные прогоны трёх вариантов, проверка критика и регрессий. Затем отдельные опыты с текстовыми skills и триггером обновления |
| M4 | Статья и воспроизводимый релиз с протоколом, конфигами и разрешёнными артефактами |

## Приёмка baseline перед реализацией памяти

1. Агент самостоятельно решает связанные SQL + RAG-задачи; проверка инструментов моками или gold SQL не считается замером качества.
2. Есть заранее выбранная небольшая открытая dev-панель и собственные проверяемые задачи; размеры и бюджет фиксируются до запуска. Закрытый итоговый тест остаётся нетронутым.
3. Сохраняются конфигурация, ревизии данных/модели/кода, prompts, seed, бюджеты, ответы, оценки и трассы. Между задачами нет памяти или доступного поиска прошлых решений.
4. Отчёт содержит качество по типам задач, число примеров, latency p50/p95 с оговоркой о размере выборки, вызовы инструментов, токены/стоимость и ошибки SQL/search/рассуждения/инфраструктуры. Неизвестные расходы явно отмечены.
5. Ошибки разобраны, отчёт воспроизводится из артефактов, ревизии и работоспособность источников подтверждены. Принятый baseline сохраняется как контрольный вариант.

Низкое качество само по себе не запрещает переход к памяти. Сначала устраняются поломки инструментов, оценщика и логирования; после этого наблюдаемые ошибки определяют, какую пользу должна принести память. Бесплатный mock-прогон подтверждает wiring, но не качество модели.


| Направление | После базовых замеров | Результат |
|---|---|---|
| Оптимизация | Реализовать предложение изменений промптов, критика и выбор версии. Подключить memory-only и позже текстовые skills | Проверяемые решения принять/пропустить и три режима одного харнесса |
| Источники | Закрепить снимки источников для replay и отдельный индекс эпизодов memory-only | Кандидаты исполняются на одинаковых данных, история изолирована по вариантам |
| Runner | Реализовать потоковый runner, слепое сравнение, реестр версий, resume и учёт всех вызовов | Опубликованная версия видна со следующего запроса, стоимость восстанавливается из manifest |
| Оценка | Подготовить открытый и собственный потоки, закрытый eval и диагностику критика | Парные результаты первых попыток, регрессии и расхождения с критиком |
