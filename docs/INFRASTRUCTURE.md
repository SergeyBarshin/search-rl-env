## Первый доступ к модели

Первый агент планируется на Qwen3.5 через аккаунт OpenRouter Сергея. Перед запуском фиксируются точный model id, провайдер, параметры генерации и лимиты. В прежнем сообщении размер был указан как 8B; проверенный ранее кандидат в этой линейке — `qwen/qwen3.5-9b`. Окончательный id ещё не зафиксирован.

Для проверки харнесса используется настраиваемый Chat Completions API. Адрес и параметры доступа задаются локально в игнорируемом .env. Команды запуска — в README.

API-инференс используется для разработки харнесса и исходной оценки. RL-обучение подключается к весам модели в тренировочном окружении. До сравнения с обученными весами потребуется исходная оценка в том же стеке, чтобы смена провайдера и точности вычислений не смешивалась с эффектом обучения.

Проверка 2026-10-31: `qwen/qwen3.5-9b` через настроенный API прошёл синтетический эпизод `search` → `finish`, выбрал `doc-001` и `doc-002`. Usage успешного эпизода: 1473 входных и 67 выходных токенов, cost `$0.00026716`. Локальный результат — `runs/api-smoke/episode-success.json` (не входит в Git). Отдельные диагностические запросы предшествовали успешному эпизоду; это не оценка качества модели. На доступном маршруте seed вызывал 404 о несовместимых параметрах, поэтому по умолчанию seed не передаётся. Также проверена совместимость с транспортным полем `index` в tool calls.

## Google Cloud

По локальному снимку от 2026-10-27 в проекте `os-jev-ru` настроены бакет `gs://os-jev-ru-data` и Batch на spot G4. Был проверен запуск обучения 2B с сохранением и возобновлением. Текущие квоты, доступность и остаток кредитов проверяются перед новым запуском.

В прежнем плане фигурировали 300 GPU-часов и API $200 в месяц; в GCP — кредиты $300. Это разные величины, не подтверждающие текущий бюджет. Разрешение на конкретные платные запуски и лимиты даёт Сергей.

## Локальные материалы прошлого проекта

На рабочей машине папка `../os_jev_ru` содержит прежний проект. Она не является зависимостью нового репозитория и не присутствует в обычном клоне.

Что можно изучить перед переносом подходящих частей:

- `format/tdfmt/tracking.py` — MLflow и снимки конфигурации;
- `format/tdfmt/metrics.py` — подход к парным сравнениям по вопросам;
- `format/tdfmt/train/` — сохранение и возобновление состояния обучения;
- `experiments/gcp/` — Batch, синхронизация и проверка артефактов;
- `format/TRAINING.md` — инструкция запуска и исторические измерения.

До копирования проверяем зависимости и допущения. Рабочие скрипты нового проекта должны запускаться из отдельного клона без обращений к соседней папке и абсолютным путям разработчика.
