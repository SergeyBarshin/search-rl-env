# Изолированные SQLite/FAISS-среды и приёмка

> Это инженерная приёмка инструментов и изоляции. Память между сессиями и самоулучшение проверяются отдельно по [MEMORY_CORE.md](MEMORY_CORE.md) и [EXPERIMENTS.md](EXPERIMENTS.md).

Реализация механизма `DB-01/02/04/03`: у каждого эпизода свой SQLite-файл,
read-only соединение и отдельный FAISS IndexFlatIP. Подготовка набора и базового
индекса выполняется один раз; при создании эпизода копируется SQLite и клонируется
индекс. Состояние диалога остаётся в публичном RolloutRunner.

Это локальный Python-адаптер SQL/search для первого спринта. Python HTTP-сервис
SQL/BM25 и его SDK сохраняются как другой способ подключения источников.
Техническая приёмка ниже использует SQLite/FAISS непосредственно в Python;
она не измеряет производительность Python HTTP API. Его отдельные проверки —
в [SQL_BACKEND.md](SQL_BACKEND.md).

## Установка и одна команда запуска

Python 3.11+, CPU, без GPU, ключей API и скачивания весов:

```bash
python -m pip install -e '.[dev,environments]'
python examples/accept_environments.py
```

Нужны пакеты FAISS, NumPy и psutil. Подмена FAISS другим индексом при отсутствии
зависимости не выполняется.

Конфиг по умолчанию — `configs/environments/acceptance.json`. Запускаются по 80
эпизодов с параллельностью 1 и 40 на одних данных, seed и бюджетах. В каждой группе
сначала идут два отдельных прогревочных эпизода; они сохраняются с phase=warmup
и не входят в измеряемые перцентили. Первая волна бесплатной модели ждёт
первого обращения всех workers. В отчёте видны число реальных обращений,
максимум одновременно активных эпизодов и сред, а не только настройка семафора.

Модель ProbeModel сценарная: запрашивает SQLite, строит поиск из полученного
keyword, затем возвращает полученные value и document id. Ответы и эталоны
в неё не зашиты. Это проверка работы среды, а не способности модели выбирать SQL.
Детерминированный `sha256-token-hashing-v1` кодирует RU/EN-слова без весов;
FAISS выполняет настоящий поиск по векторам. Такой энкодер не является
выбранной семантической моделью или показателем качества retrieval.

Консоль и `events.jsonl` показывают id эпизода, фазу и прогресс; тексты вопросов,
SQL и содержимое наблюдений в журнал событий не дублируются. Ctrl+C и SIGTERM
отменяют задачи, сохраняют доступные частичные EpisodeResult и закрывают среды.
Повторный запуск получает новый каталог; существующий `--output` не перезаписывается.
Возобновление попыток и загрузку в MLflow/GCS добавляет runner Коли.

## Что находится в результате

По умолчанию создаётся новый `runs/environments/<UTC>-<id>/`:

- `manifest.json`: конфиг, версии кода/Python/платформы, источники и ревизии,
  подготовка, сводки 1/40, список попыток и итог освобождения ресурсов;
- `datasets/`: подготовленные SQLite, FAISS, JSONL и манифесты с SHA-256;
- `c1/` и `c40/`: группы warmup/measured с полными `*.episode.json`
  и `*.binding.json` с привязкой каждой попытки к среде;
- `events.jsonl`: прогресс и времена событий без содержимого задачи.

Для измеряемой группы сохраняются эпизоды/мин, p50/p95 SQL/search/эпизода,
время модели, overhead харнесса, создание/закрытие среды и sampled peak RSS
процесса вместе с дочерними процессами. RSS опрашивается каждые 20 мс и может
не захватить более короткий пик. Время группы включает запуск/закрытие runner,
создание сред и запись результатов; подготовка набора и прогрев вынесены отдельно.
Overhead харнесса — остаток episode wall time после модели и инструментов,
а не измерение чистого CPU.

`passed` в этом отчёте означает корректность синтетических ответов, требуемый
максимум активных эпизодов/сред и освобождение ресурсов. Численный SLO скорости
пока не согласован и явно отмечен в limitations. Для полной приёмки DoD нужны
также согласованный порог и отдельно разрешённый реальный OpenRouter-прогон.
Синтетические измерения не являются официальными метриками HyDRA или других наборов.

Полная Trace содержит приватные эталоны. Артефакты прогонов должны храниться
с ограничениями доступа к разметке; не публикуйте их автоматически на внешних задачах.

## Подключение другого набора

`examples/fixtures/environments/alpha/manifest.json` и `beta/manifest.json`
показывают два разных источника. У них совпадает doc_id `doc-shared`, но отличаются
строки SQL и тексты. Тесты проверяют выбор БД/корпуса/ревизии и отсутствие подмены.

DatasetSpec содержит version=1, dataset_id, db_id, sql_path, sql_sha256,
sql_format, corpus_id, corpus_path, corpus_sha256 и dimensions. Пути относительны
файлу манифеста. Основной sql_format — `sqlite`: самостоятельный неизменяемый файл
с известным SHA-256. `fixture_sql` предназначен для доверенного локального
build-скрипта синтетики; такой скрипт выполняется при подготовке с правами процесса.
Не используйте его для SQL, сгенерированного агентом.

JSONL содержит doc_id, text и необязательные title/language. Неизвестные поля,
пустые документы и повторные id внутри корпуса отклоняются. Вопросы и эталоны
в корпус не входят. Схема SQLite извлекается из источника. Векторы, параметры
энкодера, FAISS/NumPy и правила ранжирования получают записанные ревизии.

Отдельный tasks.json связывает AgentTask с dataset_id; reference_path указывает
на приватный вход оценщика, который удаляется до передачи задачи модели.
Добавьте другой манифест и задачи в конфиг: цикл агента менять не нужно.
Для бесплатного ProbeModel синтетические таблицы должны соответствовать его
контрольному сценарию facts; произвольный SQL-набор использует настоящую модель
или свою реализацию ChatModel через `run_acceptance(..., model=...)`.

## Передача runner Коли

```python
from search_rl_env.agent import RolloutRunner
from search_rl_env.search import EnvironmentFactory

async with EnvironmentFactory(dataset_manifests) as environments:
    async with RolloutRunner(model, concurrency=40) as runner:
        async with environments.open(dataset_id) as env:
            env.validate_task(task)
            result = await runner.run(task, search=env.search, sql=env.sql,
                                      reference_answer=private_answer)
            # Сохранить result и env.manifest, связав их по result.episode_id.
```

Runner открывает контекст на каждую попытку, не передаёт привязку между задачами
и сохраняет манифест рядом с EpisodeResult. Выход по успеху/ошибке/отмене закрывает
инструменты до удаления файлов. Отмена SQLite вызывает interrupt и дожидается
worker, чтобы native-запрос не продолжал читать уже удалённый снимок.

SQLite authorizer запрещает запись, ATTACH, PRAGMA и чтение посторонних/виртуальных
таблиц. Действуют query_only, immutable, deadline, VM budget, ограничения строк,
колонок, значений и размера результата. Ошибка запроса возвращается как SqlQueryError;
повреждение/подмена снимка остаётся инфраструктурной ошибкой.

## Реальная модель и проверки

После отдельного разрешения бюджета тот же сценарий поддерживает существующий
OpenRouterClient. Ключ берётся через общий load_api_key, в конфиги не записывается:

```bash
python examples/accept_environments.py --openrouter-model MODEL_ID \
  --allow-paid --budget-usd BUDGET --request-reserve-usd UPPER_ESTIMATE
```

Числа вместо BUDGET и UPPER_ESTIMATE задаются из разрешённого бюджета и верхней
оценки стоимости запроса. Перед dispatch резервируется сумма; при неизвестной
стоимости, ошибке или превышении резерва новые запросы блокируются. Это клиентский
предохранитель по оценке, не жёсткое ограничение биллинга провайдера. Фактическая
известная стоимость и оставшиеся резервы записываются в manifest. Прогрев также платный.
Сейчас такой прогон не выполнялся.

```bash
python -m pytest tests/unit/search -q
python -m pytest tests/integration/test_environment_acceptance.py -q
```

CI в `.github/workflows/backend.yml` устанавливает CPU-зависимости, проверяет Python, запускает сравнение 1/40 и сохраняет артефакт приёмки. Без FAISS
соответствующие локальные интеграционные тесты явно пропускаются. Успешность
CI или полного прогона нужно подтвердить реальными логами; наличие workflow
само по себе не означает завершённую приёмку.

## Проверка в Docker

`sh scripts/check-docker.sh` запускает Colima при необходимости, собирает
Dockerfile и выполняет полный набор тестов и техническую приёмку 1/40.
Контейнер по умолчанию ограничен одним CPU, 3 ГБ памяти и 512 процессами/потоками.
Другой CPU-лимит задаётся через SEARCH_RL_DOCKER_CPUS; при сравнении результатов
фиксируйте одинаковые ограничения. Первый сохранённый прогон использовал два CPU.
Проверки используют только loopback внутри контейнера (`--network none`);
доступ к registry/PyPI нужен на этапе сборки. Веса моделей и API-ключи не нужны.

Результаты каждой попытки находятся в отдельном `runs/docker/run-*/`:
pytest.log, pytest.xml, acceptance.log, packages.txt, checks.json и acceptance/.
Оба этапа выполняются даже при ошибке тестов; ненулевой статус любого этапа
делает проверку неуспешной. CI запускает ту же команду и сохраняет эти файлы.

На 17.11 контейнер запущен из терминала пользователя. В попытке
`runs/docker/run-SHwYRJy8/acceptance/manifest.json` технический прогон прошёл:
по 80/80 правильных эпизодов при параллельности 1 и 40, фактический максимум
40 эпизодов/сред, ресурсы освобождены. Получено примерно 1294 и 2149 эпизодов/мин
соответственно; это синтетическое измерение без согласованного SLO.

Полный pytest этой попытки остановился при сборе из-за одинаковых имён тестов
поиска и UI. Тест поиска переименован в test_python_search_server.py;
локально подтверждён сбор всех 183 тестов. На тот момент полный контейнерный pytest требовал повторного запуска;
последующий успешный результат приведён выше. Сокет Colima остаётся недоступным
из текущей песочницы.

Повторная попытка `runs/docker/run-Uf7ltaZJ` подтвердила приёмку 1/40
и дала 182 passed / 1 failed в pytest. Единственный сбой — 15-секундный
таймаут запуска CLI в тесте проверки платных флагов. Тяжёлые импорты
перенесены после разбора и проверки аргументов; локально тест исправления
проходит. Повторить только pytest можно через
`sh scripts/check-docker.sh --tests-only`; при этом отдельный замер 1/40
не запускается и в checks.json записывается acceptance_exit_code=null.

Заключительная попытка `runs/docker/run-AMEoJ8ij` закрыла ошибку запуска CLI:
полный pytest — 183 passed без пропусков. Дополнительные платные API-запросы
и повторный отдельный замер 1/40 в этой попытке не выполнялись.
