# Близкие работы по накоплению опыта и поисковым агентам

Актуальный обзор SQL + RAG на 2026-11-01 — в [HYBRID_RESEARCH.md](HYBRID_RESEARCH.md): датасеты и доступность артефактов, обучение и результаты, публикации, варианты judge reward и предлагаемый протокол.

Разрабатываем собственный GEPA-like оптимизатор для собственного Text-to-SQL + RAG-харнесса. Между пользовательскими запросами он анализирует завершённые траектории и отбирает версии инструкций. Сначала меняются промпты, затем добавляется создание и редактирование текстовых skills. Веса модели фиксированы. Решение — [MEMORY.md](../MEMORY.md), ядро памяти — [MEMORY_CORE.md](MEMORY_CORE.md), статья — [PAPER_PLAN.md](PAPER_PLAN.md).

Материалы распределены по участникам и этапам в [TASKS.md](TASKS.md): сначала харнесс и baseline, затем углублённое изучение и реализация памяти.

## Постоянная память и использование опыта

| Работа | Близкая идея | Что сопоставить до основного прогона |
|---|---|---|
| [Hermes Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) и [Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator) | Постоянные записи, поиск истории сессий и обслуживание | Центральный системный ориентир; фиксировать версию, реально используемые компоненты и результаты всей памяти |
| [ExpeL](https://arxiv.org/abs/2308.10144) | Извлечение знаний из опыта и использование прошлых эпизодов при решении | Формат выводов, выбор примеров, обратная связь и перенос |
| [Agent Workflow Memory](https://arxiv.org/abs/2409.07429) | Извлечение повторно используемых процедур и их выбор для последующих задач | Представление процедуры, условия применения, режим накопления и контекст |
| [ACE](https://arxiv.org/abs/2510.04618) | Обновляемые инструкции с генерацией, рефлексией и курированием | Правила изменения памяти, сохранение полезных записей и оценка адаптации |
| [Hermes Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) и [Self-Evolution](https://github.com/NousResearch/hermes-agent-self-evolution) | Создание/использование skills; оптимизация навыков через DSPy и GEPA | Системный цикл, версии и доступная обратная связь; какие компоненты реализованы и как измеряется эффект |
| [GEPA](https://arxiv.org/abs/2507.19457) | Оптимизация текстовых параметров по траекториям | Эффект общего промпта при том же потоке опыта и учёте всех вызовов |

Hermes — ориентир ядра постоянной памяти. ACE/ExpeL и GEPA — возможные дополнительные сравнения после пилота. Конкретные адаптации, feedback и расходы раскрываются; упрощённый аналог не объявляется полным воспроизведением. Процедуры и gate не подменяют оценку всей системы.

## Обучение поисковых агентов

| Работа | Что предоставляет | Что сопоставлять с нашей средой |
|---|---|---|
| [Search-R1](https://arxiv.org/abs/2503.09516v5) и [код](https://github.com/PeterGriffinJin/Search-R1) | RL для чередования рассуждений и поисковых действий; маскирование текста результатов поиска при обучении | Контракт инструментов, тренировочный цикл, награду, данные и воспроизведение обучения |
| [T-Search](https://arxiv.org/abs/2610.06782) и [харнесс](https://github.com/turbo-llm/t-search-harness) | Поиск по фиксированному корпусу, ранжированные свидетельства, SFT и GSPO с recall-наградой, RU/EN-оценку | Устройство среды, инструменты, подключение других моделей и пример обучения |
| [GEPA](https://github.com/gepa-ai/gepa) | Оптимизацию текстовых параметров с обратной связью по траекториям | Отдельный эффект оптимизации промпта, стоимость поиска кандидатов и разделение train/dev/test |

README T-Search предупреждает о зависимости модели от исходных промптов, схем инструментов и ограничений. Для вариантов накопления опыта используется один контракт среды с фиксированными инструментами и данными. Опубликованные числа из другого харнесса не являются непосредственно сопоставимой строкой нашей таблицы.

Из протокола T-Search берём публичный Qwen3-Embedding-8B-ретривер и способ подсчёта Recall@10. Прямой и агентный поиск сравниваем на одной выборке через наш харнесс. Для локальной Jina отдельно проверяем вклад BM25. [Протокол T-Search](https://arxiv.org/html/2610.06782#A3.SS4) · [Наш план измерений](EXPERIMENTS.md#план-замеров-на-публичных-наборах).

## Наборы для оценки

[BrowseComp-Plus](https://huggingface.co/datasets/Tevatron/browsecomp-plus) содержит 830 вопросов и корпус из 100 195 документов. Различаются evidence documents и gold documents, содержащие финальный ответ. Для награды фиксируем конкретный набор релевантности.

Retrieval-метрики BrowseComp-Plus проверяются по qrels. Официальная accuracy свободного ответа использует LLM-судью; детерминированный exact match не эквивалентен этой accuracy. [Описание оценщика](https://github.com/texttron/BrowseComp-Plus/blob/main/docs/llm_as_judge.md).

[TRuST](https://huggingface.co/datasets/t-tech/TRuST) содержит 324 русских вопроса, [SynthComp](https://huggingface.co/datasets/t-tech/SynthComp) — по 395 в RU и EN. TRuST использует оценку уровня документов. Preview имеет техническое имя split `train`, но карточки запрещают обучение на preview и публикацию расшифрованной версии. В нашем проекте вопросы этих наборов используются только для внешней оценки.

## Позиционирование статьи

GEPA предлагает и проверяет изменения инструкций по траекториям. Harness² исследует адаптацию харнесса без ground-truth verifier и перенос опыта между задачами. Наш исследовательский вопрос касается отбора версий на потоке SQL + RAG и независимой оценки их будущей пользы относительно памяти и статического харнесса. [GEPA](https://arxiv.org/abs/2507.19457) · [Harness²](https://arxiv.org/abs/2610.14224).

Hermes служит ориентиром для memory-only. При интерпретации различаем режимы нашей реализации и полные внешние системы. [Методика](EXPERIMENTS.md).
