# Дизайн открытой среды обучения поисковых агентов

Проект спецификации от 2026-10-30. Среда предоставляет агенту задачу, поисковые инструменты и награду за результат. Агент учится формулировать запросы, использовать найденные материалы и завершать задачу. Последовательность действий сохраняется для обучения и оценки.

## Первый пример использования

Предлагаемый первый пример — поиск свидетельств по вопросу в фиксированном корпусе. Агент возвращает ранжированный список найденных документов. Качество проверяется по размеченным релевантным документам без LLM-судьи.

Начальная основная метрика — Recall@10: доля известных релевантных документов, попавших в первые десять уникальных результатов агента. Это предложение для первого примера; конкретный набор релевантности и единицу оценки фиксируем при выборе данных. Режим с финальным текстовым ответом может использовать другую проверяющую функцию при том же цикле среды.

## Задача и наблюдение

| Часть | Содержание |
|---|---|
| Доступно агенту | Вопрос, язык, инструменты, остаток бюджета и история наблюдений |
| Доступно среде | Id и ревизия корпуса, конфигурация поиска и ограничения эпизода |
| Доступно только оценщику | Эталонные документы или ответы, правила проверки и группа разбиения |

Qrels — размеченные соответствия между вопросами и релевантными документами. Эталонная разметка не передаётся агенту. Документ имеет постоянный `doc_id`, чанк — отдельный `chunk_id` и родительский `doc_id`. Адаптер набора задаёт единицу оценки: при оценке по документам несколько чанков одного документа дают одно попадание.

## Действия

| Действие | Аргументы | Результат |
|---|---|---|
| `search` | Текст запроса | Упорядоченные кандидаты с id, сниппетами и оценкой поиска |
| `read` | Id обнаруженного чанка | Текст в пределах лимита чтения |
| `finish` | Упорядоченные id найденных свидетельств | Завершение эпизода и оценка результата |

Первый прототип реализует только `search` и `finish`. Остановка является действием самой модели, она же выбирает число поисков. Внешний конфиг ограничивает шаги и выходные токены; отдельный `max_searches` необязателен и по умолчанию равен `None`. Ограничены также число результатов и длина сниппета; полноценный подсчёт и обрезка контекста пока не реализованы. Число результатов и длина показанного текста должны быть одинаковы до и после обучения. Точная семантика первого харнесса — в [CONTRACTS.md](CONTRACTS.md).

В `finish` разрешены только ранее показанные id. Повторы удаляются с сохранением порядка. Невалидный формат, придуманные id и превышение лимита фиксируются; ограниченные исправления расходуют шаги и токены. Различаем добровольное завершение, исчерпание бюджета, невалидные действия и инфраструктурный сбой. При исчерпании бюджета харнесс сохраняет пустой финальный список и `truncated=true`, без дополнительного вызова модели. Показанные документы остаются в истории, поэтому recall поиска можно посчитать отдельно от отбора. Сбои сервиса учитываются отдельно от качества модели.

## Награда

Для первого примера предлагаем терминальную награду:

```text
R = |top_10_unique_document_ids ∩ relevant_document_ids|
    / |relevant_document_ids|
```

Пустое эталонное множество в эту задачу не допускается. Повторная выдача документа не увеличивает число попаданий. Размер финального списка ограничен, поэтому выдача всего корпуса не позволяет обойти задачу.

Основная цель — повысить качество поиска при фиксированных ограничениях эпизода. Штраф за стоимость не требуется в первой версии. Реальные затраты измеряются отдельно. Recall всех показанных документов и recall финального списка различаются: они показывают качество поиска и качество отбора результата. Отсутствие документа в неполных qrels не доказывает его нерелевантность.

Для задач с ответом подключается отдельный проверяющий код. В BrowseComp-Plus официальная accuracy свободного ответа использует LLM-судью; она публикуется отдельно от детерминированных retrieval-метрик. [Описание оценщика](https://github.com/texttron/BrowseComp-Plus/blob/main/docs/llm_as_judge.md).

## Интерфейс и обучение

```text
reset(task, seed) -> observation
step(action) -> observation, reward, terminated, truncated, info
```

Среда выполняет действия и оценивает результат. Харнесс передаёт модели историю, получает её действия, вызывает инструменты среды и возвращает результаты модели. Алгоритм RL обновляет модель по собранным эпизодам. Такой контракт позволяет подключать разные модели и тренировочные библиотеки.

Первый путь инференса — Qwen3.5 через OpenRouter. Клиент вызова модели находится внутри харнесса; создание отдельного сервиса для него не требуется. Доступ через API позволяет отлаживать цикл агента до развёртывания модели на GPU.

Цикл примера: выбрать train-вопросы → собрать роллауты текущей модели в среде → получить награды → обновить параметры агента → сохранить чекпоинт → периодически оценить на фиксированном dev-наборе.

Текст результатов инструментов является наблюдением среды. При обучении на сериализованной траектории маска loss исключает эти токены. Пример обучения должен демонстрировать весь путь от запуска среды до оценки чекпоинта.

## Журнал и воспроизводимость

Сохраняются версия схемы, id задачи и эпизода, split, seed, хеши корпуса, индекса, кода и конфигурации; ревизия модели, dtype, промпт и параметры декодирования; наблюдения, действия, результаты инструментов и обрезка контекста; причина завершения, финальный список и компоненты награды.

Учёт ресурсов включает поисковые вызовы, входные и выходные токены, время поиска и инференса, GPU-время и API-расход при доступности. Недоступная телеметрия имеет значение `null`, не ноль. Логи и конфигурации сохраняются через MLflow. Возобновление обучения восстанавливает оптимизатор, шаг, RNG и id эксперимента.

Воспроизведение сохранённого эпизода проверяет среду и оценщик. Новая модель может выбирать другие действия, поэтому её качество измеряется новыми роллаутами на тех же задачах и при тех же ограничениях.
