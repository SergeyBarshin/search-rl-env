# search-rl-env

Проект открытой RL-среды для обучения поисковых агентов по фиксированному корпусу документов. Агент получает вопрос, обращается к поиску, собирает свидетельства и возвращает результат. Среда предоставляет инструменты, ограничения эпизода и оценку.

На собственном агенте покажем обучение в этой среде: исходное качество, кривые обучения и результат на отложенных задачах. Рост метрики проверяется на вопросах, которые не использовались для обновления модели.

## Текущее состояние

Реализован первый харнесс: `run_episode(task, model, search, config)` выполняет цикл модели с инструментами `search` и `finish`, проверяет действия и бюджеты, возвращает историю и расход ресурсов. Есть детерминированные моки, клиент OpenRouter Chat Completions и сохранение результата в JSON. Тесты и пример работают без сети, ключей, весов и GPU. Обучение, реальные поисковые бэкенды, оценщики и MLflow ещё не подключены.

Для Qwen через OpenRouter model id задаётся явно в CLI или `OPENROUTER_MODEL`. Пример RL-обучения затем подключается к весам модели в тренировочном окружении.

## Как устроена работа

| Участник | Ответственность | Планируемые модули |
|---|---|---|
| **Сергей** | Агент, харнесс и модели: цикл действий, промпты, контекст, клиенты моделей, ограничения эпизода и RL | `agent/`, `training/` |
| **Дима** | База данных и поиск: хранение корпуса, индексы, поисковые ручки и чтение документов | `search/` |
| **Коля** | Инфраструктура снятия бенчмарков поверх харнесса и поиска: конфиги прогонов, возобновление, метрики, затраты и отчёты | `evaluation/` |
| **Вова** | Бенчмарки: задачи, эталоны, метрики, джаджи и проверка качества оценки | `benchmarks/` |

Инфраструктура Коли запускает задачи Вовы через харнесс Сергея. Агент обращается к поиску Димы. Результаты проходят через оценщики Вовы, а runner сохраняет оценки и отчёт. Подробные первые задачи — в [TASKS.md](docs/TASKS.md).

## Структура репозитория

Реализованы `contracts/`, `agent/`, пример и тесты. Остальные компоненты ниже остаются планом:

```text
src/search_rl_env/
├── contracts/      # типы задачи, поиска, конфигурации и результата
├── agent/          # цикл, инструменты, промпт, OpenRouter и моки
├── training/       # план: обучение
├── search/         # план: корпус и поиск
├── benchmarks/     # план: задачи, метрики и джаджи
└── evaluation/     # план: прогоны и отчёты
examples/run_episode.py # запуск одного вопроса
examples/fixtures/  # синтетический вопрос и подставная выдача без эталонов
tests/unit/agent/   # цикл, HTTP-протокол и пример запуска
docs/              # спецификации, решения и план
```

Полное дерево, владельцы и правила размещения данных — в [STRUCTURE.md](docs/STRUCTURE.md). Общие интерфейсы согласуются по примерам из [CONTRACTS.md](docs/CONTRACTS.md).

## Как начать

```bash
git clone https://github.com/SergeyBarshin/search-rl-env.git
cd search-rl-env
```

Прочитайте [правила работы](CONTRIBUTING.md), свою задачу в [TASKS.md](docs/TASKS.md) и затронутые контракты. До разработки создайте issue с результатом и способом проверки, затем рабочую ветку. Изменения вливаются в `main` через PR с ревью.

Нужен Python 3.11+. Установка из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Если используете uv: `uv venv .venv`, затем `uv pip install -e '.[dev]'` и `source .venv/bin/activate`.

Бесплатный эпизод на моках:

```bash
python examples/run_episode.py --output runs/demo/episode.json
```

Ожидаемый результат: `stop_reason=finished`, документы `doc-001`, `doc-002` и JSON в указанном файле. Мок выбирает все показанные документы в пределах `max_documents`; это проверка взаимодействия, а не качества отбора. `runs/` исключён из Git. CLI возвращает код `0` при `finished`, `1` при остановке эпизода по другой причине.

Модель сама выбирает запросы, число поисков и момент `finish`. Отдельный лимит поисков по умолчанию отсутствует (`max_searches=None`); его можно включить через `--max-searches`. Весь эпизод ограничен `--max-steps` (по умолчанию 6 ответов модели) и `--max-output-tokens` (2048 суммарных выходных токенов). Один ответ ограничен `--max-tokens-per-step` (512). Это бюджеты прогона; принудительная остановка по бюджету сохраняется с `truncated=true` и пустым финальным списком. Показанные документы остаются в истории.

Для подключения настоящей модели сохраните `OPENROUTER_API_KEY` в локальном `.env` или переменной окружения; пустой образец — [.env.example](.env.example). `.env` загружается только в OpenRouter-режиме, переменные окружения имеют приоритет. Пример команды **для отдельно разрешённого платного запуска**; поиск остаётся моковым:

```bash
python examples/run_episode.py --model openrouter --model-id qwen/qwen3.5-9b \
  --max-steps 6 --max-output-tokens 2048 --max-tokens-per-step 512 \
  --output runs/openrouter-demo/episode.json
```

Клиент следует [протоколу tool calling OpenRouter](https://openrouter.ai/docs/guides/features/tool-calling): передаёт схемы при каждом запросе и возвращает результаты через `role="tool"` с исходным `tool_call_id`. Запросы не повторяются автоматически. Поддержку параметров и доступность модели проверяет провайдер; локальные тесты не проверяют платный endpoint.

Проверки:

```bash
python -m pytest -q
git diff --check
```

Тесты покрывают несколько поисков по решению модели, нормальное завершение, бюджеты, повторы id, неизвестные документы, исправление ошибочных действий, сбои, JSON-сохранение и воспроизведение. HTTP-вызовы OpenRouter проверяются через `httpx.MockTransport`, без сети. Точные интерфейсы для поиска Димы и runner Коли — в [CONTRACTS.md](docs/CONTRACTS.md).

## Первый совместный результат

1. **Общий пример:** Вова готовит небольшой синтетический корпус, вопросы, эталоны и примеры оценок.
2. **Контракты:** Сергей и Дима согласуют поиск; Сергей и Коля — вызов харнесса; Вова и Коля — оценщики.
3. **Компоненты:** поиск отвечает по корпусу, агент проходит один эпизод, runner сохраняет результат и считает метрику.
4. **Исходная оценка:** одинаковый набор запускается по конфигу с сохранением траекторий и затрат.
5. **Обучение:** подключается тренировочный цикл, затем сравниваются исходная и обученная модели.

Для первого retrieval-примера предложен Recall@10. Конкретные задачи, единица оценки и награда остаются предметом спецификации; фиксация происходит до сравнительного прогона. План проверки — в [EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Данные и воспроизводимость

В Git хранятся код, конфиги, манифесты и небольшой синтетический пример. Большие корпуса, индексы, веса, траектории и артефакты находятся во внешнем или локальном хранилище. Источники данных и их версии фиксируются, оценочные вопросы и эталоны не используются для обучения.

Для экспериментов сохраняются версии кода и данных, параметры моделей, seed, промпты, лимиты, траектории, метрики и расходы. Трекинг — MLflow. Ключи API передаются через локальную конфигурацию; платные запуски имеют согласованный бюджет.
